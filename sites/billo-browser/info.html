Billo Browser — all the information

Everything about the creator browser: what it is, where it lives, how it works, how to rebuild it, and what it connects to.

1. What it is

A browser we own, built in Rust on macOS's WebKit engine. It replaces Chrome for automated and creator work: no shared profile, no menu toggle, no CDP launch flags, no extension store. Its start page is a live dashboard of Billo OS data served by a local bridge.

3. How to run it

# bridge  (serves stats/search/open to the start page and any device that can reach it)
python3 ~/BillySorrells/scripts/billo_serve.py

# browser window
~/BillySorrells/tools/billo-browser-rs/target/release/billo_browser

# rebuild after editing (3 seconds)
cd ~/BillySorrells/tools/billo-browser-rs && cargo build --release

# headless CLI (scrape / screenshot from any model)
billo text https://site.com
billo dump https://site.com
billo shot https://site.com out.png
billo --engine webkit text https://site.com
billo session https://site.com        # real window, persistent logins

8. Why not Chrome

  • Chrome's profile is personal — automation either touched real logins or needed a password.
  • JS from AppleScript requires a manual menu toggle that can't be set from the shell.
  • CDP is blocked on the default profile in current Chrome builds.
  • Chrome background data reached 9 GB of profiles and 65 GB of code-sign temp clones.
  • One engine means you can't test how a page behaves outside Chromium.
